# 校园网络安全态势感知系统 -- 创新算法设计文档

## 文档概述

本文档详细阐述了校园网络安全态势感知系统中四项核心创新算法的设计理念、数学原理、技术实现及创新价值。四项算法均基于对系统原有六大检测模块（DDoS检测、端口扫描检测、慢速扫描检测、蠕虫传播检测、钓鱼攻击检测、数据外泄检测）及流量分析引擎的组合设计与工程实现创新。文中 EWMA、Shannon 熵、Z-score、Gini 系数、Pearson 相关、线性回归、并查集和 Cyber Kill Chain 均按通用统计/安全模型思想引用，不宣称这些基础方法本身原创。

## 二、算法一：EWMA-Entropy 自适应异常检测算法 (EWMA-EAD)

### 2.1 问题背景与动机

原系统威胁检测采用"均值x倍数"的简单动态阈值方法（如DDoS阈值 = max(700MB, 历史平均 x 3)），这种方法存在以下不足：

1. **响应滞后**：简单均值对短期变化不敏感，无法快速适应流量模式转变
2. **单维度判断**：仅依据流量体积，忽略了行为模式（协议分布、时间分布等）的变化
3. **无法检测隐蔽攻击**：攻击者可以控制流量在阈值以下，但通过改变行为模式实施攻击

### 2.2 核心创新

**将三个独立的分析维度融合为一个统一的异常评分模型：**

- **维度1 - 流量体积偏差（Volume Deviation）**：采用EWMA替代简单均值，实现自适应基线追踪
- **维度2 - 信息熵偏差（Entropy Deviation）**：引入Shannon信息熵度量协议分布变化
- **维度3 - 时间突发度（Temporal Burstiness）**：基于流到达间隔的变异系数检测突发行为

### 2.3 数学模型

#### 2.3.1 指数加权移动平均（EWMA）

EWMA通过指数衰减权重对历史数据加权，近期数据权重更高：

```
EWMA均值更新：
    μ_t = α · x_t + (1 - α) · μ_{t-1}

EWMA方差更新：
    σ²_t = α · (x_t - μ_{t-1})² + (1 - α) · σ²_{t-1}

其中：
    α = 0.3（平滑因子，控制对新数据的敏感度）
    x_t 为当前观测值
    μ_t 为当前EWMA均值估计
    σ²_t 为当前EWMA方差估计
```

**与原系统对比**：原系统使用过去1小时的简单算术平均值，权重均匀分布，无法区分近期和远期变化。EWMA以指数衰减权重赋予近期数据更大影响力，平滑因子α=0.3意味着最近3个时间桶贡献了约65%的权重。

#### 2.3.2 Shannon 信息熵

协议分布熵度量流量的行为多样性：

```
H(X) = -Σ p_i · log₂(p_i)

其中 p_i 为第i种应用协议在当前时间桶中的占比
```

**创新意义**：
- 正常校园网络的协议分布熵相对稳定（HTTP/HTTPS主导，DNS辅助等）
- 端口扫描攻击会导致熵值突增（大量不同协议出现）
- DDoS攻击会导致熵值突降（单一协议流量暴增）
- 熵的偏离方向与幅度都携带攻击类型信息

#### 2.3.3 时间突发度系数

基于流到达间隔的变异系数（Coefficient of Variation）：

```
设流到达时间戳排序后为 t_1, t_2, ..., t_n
到达间隔 Δ_i = t_{i+1} - t_i

突发度 CV = σ(Δ) / μ(Δ)

其中：
    μ(Δ) = 到达间隔的均值
    σ(Δ) = 到达间隔的标准差
```

**创新意义**：
- CV ≈ 0：流量均匀到达（正常基线流量）
- CV >> 1：流量高度突发（DDoS、扫描等攻击行为典型特征）
- 与流量体积无关，能检测到体积不超标但时间模式异常的攻击

#### 2.3.4 复合异常评分

三维度融合的复合异常评分：

```
Z_volume = (x - μ_ewma) / σ_ewma    （流量Z分数）
Z_entropy = (H - μ_H_ewma) / σ_H_ewma  （熵Z分数）
Z_burst = (CV - μ_CV_ewma) / σ_CV_ewma  （突发度Z分数）

归一化（Sigmoid映射到[0,1]）：
    S(z) = 1 / (1 + e^(-|z| + 2))

最终异常评分：
    AnomalyScore = 0.40 × S(Z_volume) + 0.35 × S(Z_entropy) + 0.25 × S(Z_burst)
```

**权重设计依据**：
- 流量体积（0.40）：最直接的异常指标，权重最高
- 信息熵（0.35）：行为模式变化的核心度量，对隐蔽攻击尤其有效
- 突发度（0.25）：时间维度的补充信号，用于检测脉冲式攻击

### 2.4 算法流程

```
输入：检测时间窗口 [T_start, T_end]
输出：异常时间线 + 告警列表

1. 获取基线数据（检测窗口前1小时）
2. 将基线数据按5分钟分桶，计算每桶的[体积, 熵, 突发度]
3. 用基线桶训练三个EWMA状态（均值+方差）
4. 将检测窗口数据按5分钟分桶
5. 对每个检测桶：
   a. 计算三维Z分数
   b. Sigmoid归一化
   c. 加权合成异常评分
   d. 用当前观测更新EWMA状态（在线学习）
   e. 若评分 ≥ 0.65，生成告警
6. 输出异常时间线和告警列表
```

### 2.5 相对于原系统的创新优势

| 对比维度 | 原系统动态阈值 | EWMA-EAD |
|----------|---------------|----------|
| 基线追踪 | 简单算术平均 | EWMA指数加权，自适应 |
| 检测维度 | 单维度（体积） | 三维度（体积+熵+突发度） |
| 隐蔽攻击 | 无法检测 | 通过熵偏差和突发度检测 |
| 在线学习 | 无 | EWMA状态随时间自动更新 |
| 评分输出 | 二值（超标/未超标） | 连续评分[0,1]，可分级告警 |

## 三、算法二：多维威胁关联推理引擎 (MDTCE)

### 3.1 问题背景与动机

原系统六种威胁检测器**完全独立运行**，每种检测器只关注单一攻击类型。然而在真实APT（高级持续性威胁）场景中，攻击者通常遵循"网络杀伤链"（Cyber Kill Chain）模型，依次执行：

```
侦察(Reconnaissance) → 武器化(Weaponization) → 利用(Exploitation) → 窃取(Exfiltration)
```

如果不同检测器产生的告警之间存在IP关联、时间邻近、地理聚集，则这些看似独立的告警很可能是同一攻击行动的不同阶段。

### 3.2 核心创新

**构建告警关联图并基于网络杀伤链模型检测多阶段攻击链：**

1. **IP重叠评分**：Jaccard相似度衡量两个告警的IP关联
2. **时间邻近评分**：指数衰减函数量化时间接近度
3. **地理聚集评分**：经纬度欧氏距离的高斯核函数
4. **杀伤链阶段映射**：将告警类型映射到杀伤链阶段，检测阶段递进

### 3.3 数学模型

#### 3.3.1 告警对关联评分

对于任意两个告警 A 和 B：

```
关联评分 = w_ip × IP重叠(A,B) + w_time × 时间邻近(A,B) + w_geo × 地理聚集(A,B)

其中：
    w_ip = 0.45, w_time = 0.30, w_geo = 0.25
```

**IP重叠（Jaccard系数）：**
```
IP_overlap(A, B) = |IPs(A) ∩ IPs(B)| / |IPs(A) ∪ IPs(B)|

其中 IPs(X) = {srcIp(X), dstIp(X)}
```

**时间邻近（指数衰减）：**
```
Temporal(A, B) = e^(-λ · |t_A - t_B|)

其中 λ = 0.1（衰减常数），|t_A - t_B| 以分钟为单位
```

**地理聚集（高斯核）：**
```
Geo(A, B) = e^(-d(A,B) / 10)

其中 d(A,B) = √((lat_A - lat_B)² + (lon_A - lon_B)²)
```

#### 3.3.2 杀伤链阶段映射

```
阶段1 - 侦察（Reconnaissance）：PortScan, SlowPortScan
阶段2 - 武器化与投递（Weaponization & Delivery）：Phishing
阶段3 - 利用与控制（Exploitation & Command）：DDoS, WormPropagation, EWMA-EAD
阶段4 - 窃取与影响（Exfiltration & Impact）：DataExfiltration
```

**杀伤链递进增强**：若两个关联告警构成杀伤链阶段递进（时间先后对应阶段先后），则关联评分乘以1.3的增强因子。

#### 3.3.3 攻击链检测（Union-Find算法）

```
1. 构建告警关联图 G = (V, E)
   V = 所有告警节点
   E = {(A,B) | 关联评分(A,B) ≥ 0.50}

2. 使用路径压缩的并查集（Union-Find）找到所有连通分量

3. 每个包含 ≥ 2个告警的连通分量构成一条攻击链

4. 计算攻击链严重度：
   ChainSeverity = 0.40 × (覆盖阶段数/4) + 0.35 × (最高严重度/4) + 0.25 × (平均严重度/4)
```

#### 3.3.4 源IP风险热力图

```
综合风险 = 基础风险 × (1 + 0.2 × 关联连接数) × (1 + 0.3 × (告警类型多样性 - 1))

归一化风险 = min(1.0, 综合风险 / 10)
```

### 3.4 算法流程

```
输入：分析时间窗口内的所有告警
输出：攻击链列表 + 关联图 + 源IP风险热力图

1. 加载时间窗口内所有告警，转换为AlertNode列表
2. 对所有告警对（时间差 ≤ 30分钟）：
   a. 计算IP重叠评分
   b. 计算时间邻近评分
   c. 计算地理聚集评分
   d. 加权合成关联评分
   e. 检测杀伤链递进，给予增强
3. 使用Union-Find在关联评分 ≥ 0.50的边上做连通分量
4. 每个连通分量 = 一条攻击链
5. 计算攻击链严重度和覆盖的杀伤链阶段
6. 聚合源IP风险热力图
7. 输出结果
```

### 3.5 创新价值

| 对比维度 | 原系统 | MDTCE |
|----------|--------|-------|
| 告警关系 | 完全独立 | 三维关联（IP+时间+地理） |
| 攻击模型 | 无 | 网络杀伤链四阶段建模 |
| 多阶段检测 | 不支持 | 自动检测跨类型攻击链 |
| 风险评估 | 单告警级别 | 攻击链整体严重度评估 |
| 可视化 | 独立告警列表 | 关联图 + 风险热力图 |

## 四、算法三：网络行为指纹与风险评分算法 (NBF-RS)

### 4.1 问题背景与动机

原系统IP画像（buildIpProfile）仅提供统计汇总信息（总字节数、总包数、对端数等），是**描述性**的。无法回答"这个IP的行为是否异常？异常程度如何？"的问题。

NBF-RS算法的目标是为每个活跃IP构建一个**多维行为特征向量（指纹）**，并基于该向量计算综合**风险评分**，实现从"描述"到"判断"的跨越。

### 4.2 核心创新

**7维行为指纹向量 + 异常敏感归一化 + 基尼系数时间集中度：**

### 4.3 数学模型

#### 4.3.1 七维行为指纹向量

每个活跃IP被表示为一个7维向量 F = (F1, F2, F3, F4, F5, F6, F7)：

**F1 - 协议熵（Protocol Entropy）：**
```
F1 = H(AppProtocol) = -Σ p_i · log₂(p_i)

p_i = 该IP使用第i种应用协议的流数占比
```
- 正常主机：H ∈ [1.5, 3.5]（使用3~12种协议）
- 扫描器：H > 4.0（探测大量协议）
- C2 Beacon：H < 1.0（只用单一协议通信）

**F2 - 对端多样性指数（Peer Diversity Index）：**
```
F2 = |unique_peers| / √(total_flows)

归一化到 [0, 1] 区间，除以参考值 3.0
```
- 设计依据：正常用户的对端数与流数呈亚线性关系
- 端口扫描器：对端极多但每对端流数极少，F2值异常高

**F3 - 流量不对称比（Traffic Asymmetry Ratio）：**
```
F3 = outbound_bytes / total_bytes

其中 outbound_bytes 为该IP作为源发出的字节数
```
- F3 ≈ 0.5：正常双向通信
- F3 → 1.0：大量上传（可能数据外泄）
- F3 → 0.0：大量下载（可能DDoS受害者或C2接收端）

**F4 - 端口离散度（Port Dispersion Index）：**
```
F4 = H(DstPort) = -Σ p_j · log₂(p_j)

p_j = 该IP访问第j个目标端口的流数占比
```
- 正常Web用户：F4 ∈ [2, 5]（主要访问80/443，偶尔其他）
- 端口扫描器：F4 > 6（访问大量不同端口）

**F5 - 时间集中度（Temporal Activity Concentration）-- 基尼系数：**

```
将分析时间窗口等分为12个时间桶
统计每个桶中该IP的流数 n_1, n_2, ..., n_12

基尼系数 G = Σᵢ(2i - n - 1) · n_sorted[i] / (n · Σn_sorted)

其中 n_sorted 为桶值的升序排列
```

**这是本算法的核心创新之一**：
- G ≈ 0：活动均匀分布在所有时间桶（正常持续通信）
- G → 1：活动高度集中在少数时间桶（突发行为，如DDoS、批量扫描）
- 基尼系数原用于经济学衡量收入不平等，本项目将其作为网络活动时间不平等性的解释性度量特征

**F6 - 连接强度（Connection Intensity）：**
```
F6 = total_flows / (time_minutes × peer_count)

即每分钟每对端的平均流数
```
- 高F6值意味着对少数对端发起密集连接，可能为暴力破解或DDoS

**F7 - 包大小偏差（Average Packet Size Deviation）：**
```
avg_pkt_size_ip = Σ(bytes) / Σ(packets)（该IP的平均包大小）
avg_pkt_size_net = 全网平均包大小

F7 = |avg_pkt_size_ip - avg_pkt_size_net| / avg_pkt_size_net
```
- 隧道流量：包大小偏大（封装开销）
- 扫描流量：包大小极小（SYN/RST等小包探测）

#### 4.3.2 异常敏感归一化

对于协议熵和端口离散度等指标，正常范围的两侧偏移都可能是异常的。因此设计了**双侧异常敏感归一化**函数：

```
AnomalySensitiveNorm(value, normalLow, normalHigh) =
    若 value < normalLow：(normalLow - value) / normalLow
    若 value > normalHigh：(value - normalHigh) / normalHigh
    否则：0（在正常范围内）

结果裁剪到 [0, 1]
```

**创新意义**：与传统的线性归一化不同，该函数只在值偏离正常范围时产生非零输出，正常范围内完全为0，避免了正常行为对风险评分的污染。

#### 4.3.3 综合风险评分

```
RiskScore = Σ w_i × Normalize(F_i)

具体为：
RiskScore = 0.15 × AnomalySensitiveNorm(F1, 1.5, 3.5)   // 协议熵
          + 0.15 × Saturate(F2 / 3.0)                     // 对端多样性
          + 0.20 × 2|F3 - 0.5|                            // 流量不对称
          + 0.15 × AnomalySensitiveNorm(F4, 2.0, 5.0)     // 端口离散度
          + 0.10 × 截断归一化(F5)                         // 时间集中度（Gini）
          + 0.15 × Saturate(F6 / 2.0)                     // 连接强度
          + 0.10 × Saturate(F7)                            // 包大小偏差

风险等级划分：
    RiskScore ≥ 0.70 → High Risk
    0.45 ≤ RiskScore < 0.70 → Medium Risk
    RiskScore < 0.45 → Low Risk
```

**权重设计依据**：
- 流量不对称（0.20）最高：最直接反映数据外泄或DDoS
- 协议熵、对端多样性、端口离散度、连接强度（各0.15）：行为模式的核心维度
- 时间集中度、包大小偏差（各0.10）：辅助信号

### 4.4 行为聚类

基于风险评分将所有活跃IP分为三个行为簇：

```
正常簇 (Normal)：RiskScore < 0.45
可疑簇 (Suspicious)：0.45 ≤ RiskScore < 0.70
恶意簇 (Malicious)：RiskScore ≥ 0.70
```

### 4.5 创新价值

## 五、算法四：时序模式挖掘与预测性告警算法 (TPM-PA)

### 5.1 问题背景与动机

原系统所有检测都是**事后型**的：只有当攻击已经发生并超过阈值后才能产生告警。本算法的目标是实现**预测性**安全告警，在异常完全显现之前发出早期预警。

### 5.2 核心创新

**多信号时序分解 + 交叉信号相关分析 + 前瞻性Z分数预测：**

### 5.3 数学模型

#### 5.3.1 多信号时间桶

系统同时追踪四个时间序列信号：

```
Signal_1(t) = 总流量字节数（volume signal）
Signal_2(t) = 总数据包数（packet signal）
Signal_3(t) = 告警频率（alert rate signal）
Signal_4(t) = 活跃IP数（active IP signal）

每5分钟一个时间桶，取桶内各信号的聚合值
```

#### 5.3.2 线性回归趋势分解

对每个信号进行线性回归分解：

```
Y = a + b·X + ε

其中：
    X = 时间桶索引（0, 1, 2, ...）
    Y = 信号观测值
    a = 截距（intercept）
    b = 斜率（slope） = (n·ΣXY - ΣX·ΣY) / (n·ΣX² - (ΣX)²)
    a = Ȳ - b·X̄
    ε = 残差（residual） = Y - (a + b·X)
```

趋势分解输出：
- **趋势分量**：a + b·X（线性趋势线）
- **残差分量**：ε（去趋势后的波动）
- **波动率**：σ_ε / μ_Y（残差标准差与均值之比）

#### 5.3.3 前瞻性预测与Z分数

基于趋势线外推未来N个桶（N=3，即预测未来15分钟）：

```
预测值 Ŷ_{t+h} = a + b · (n + h)    （h = 1, 2, 3）

预测Z分数 Z_{t+h} = (Ŷ_{t+h} - μ_Y) / σ_Y
```

**Z分数阈值**：
- |Z| ≥ 1.5：Warning级别
- |Z| ≥ 2.5：Critical级别

#### 5.3.4 交叉信号相关分析

**这是本项目组合设计的核心环节**：当多个独立信号同时偏离基线时，提高异常可信度评分。

**Pearson相关系数**（度量信号间线性关系）：

```
r(X, Y) = Σ(X_i - X̄)(Y_i - Ȳ) / √(Σ(X_i - X̄)² · Σ(Y_i - Ȳ)²)
```

计算所有6个信号对的相关系数：
- bytes_packets, bytes_alerts, bytes_uniqueIps
- packets_alerts, packets_uniqueIps, alerts_uniqueIps

**交叉信号放大效应**：

```
基础早期预警分数 = Sigmoid(max(|Z_1|, |Z_2|, |Z_3|, |Z_4|) - 1)

统计超过Warning阈值的信号数 K

若 K ≥ 2：预警分数 ×= 1.4（两个信号同时异常）
若 K ≥ 3：预警分数 ×= 1.4 × 1.4 = 1.96（三个信号同时异常）

最终 Early Warning Score = min(1.0, 放大后的预警分数)
```

**创新依据**：
- 单一信号异常可能是随机波动
- 两个独立信号同时异常的概率 = P₁ × P₂（远低于单信号）
- 三个信号同时异常几乎可以确定为真实攻击前兆
- 放大因子1.4是基于信号独立假设下的贝叶斯后验更新的简化近似

#### 5.3.5 变化率分析

除了绝对Z分数，还分析各信号的变化速率：

```
bytesRateOfChange = slope_bytes / mean_bytes    （相对斜率）
alertRateOfChange = slope_alerts / mean_alerts
```

正的高变化率预示流量/告警正在加速增长，是攻击即将达到高峰的早期信号。

### 5.4 算法流程

```
输入：分析时间窗口 [T_start, T_end]
输出：趋势分析 + 未来15分钟预测 + 早期预警

1. 获取时间窗口内所有流量和告警数据
2. 按5分钟分桶，每桶计算4个信号值
3. 对每个信号做线性回归趋势分解
4. 计算6对信号间的Pearson相关系数
5. 外推未来3个桶（15分钟），计算预测Z分数
6. 统计超Warning的信号数，应用交叉信号放大
7. 生成早期预警评分和等级
8. 输出历史分析（含趋势线、残差、Z分数）和预测结果
```

### 5.5 创新价值

| 对比维度 | 原系统 | TPM-PA |
|----------|--------|--------|
| 检测模式 | 事后检测 | 预测性提前预警 |
| 信号维度 | 单信号（体积） | 四信号并行分析 |
| 趋势分析 | 无 | 线性回归分解 |
| 信号交互 | 无 | Pearson相关 + 交叉放大 |
| 预测能力 | 无 | 外推未来15分钟 |
| 变化率 | 无 | 相对斜率分析 |

## 六、四算法协同工作机制

四个创新算法并非孤立运行，而是形成一个多层次的安全态势感知体系：

```
时间轴 ──────────────────────────────────────────────►

Layer 1 - 预测层 [TPM-PA]
    │  提前15分钟预警："流量趋势异常，预计即将发生攻击"
    ▼
Layer 2 - 实时检测层 [EWMA-EAD]
    │  实时检测："当前5分钟窗口异常评分0.82，熵偏差主导"
    ▼
Layer 3 - 行为分析层 [NBF-RS]
    │  精确定位："IP 203.0.113.45 风险评分0.89，流量不对称严重"
    ▼
Layer 4 - 关联推理层 [MDTCE]
    │  攻击链还原："检测到完整杀伤链：侦察→利用→窃取"
    ▼
最终输出：综合态势报告
```

## 八、算法创新点总结

### 8.1 组合设计创新

1. **EWMA-Entropy融合模型**：在本项目工程场景中将通用时间序列自适应建模（EWMA）、信息论（Shannon熵）和统计学（变异系数）组合为统一的异常评分框架
2. **网络杀伤链图关联算法**：借鉴 Cyber Kill Chain、Jaccard相似度、指数衰减、高斯核和Union-Find等通用思想，形成适配本项目告警数据的攻击链发现流程
3. **基尼系数在网络时间行为分析中的应用**：复用经济学中衡量收入不平等的通用 Gini 系数，作为本项目网络流量时间分布不平等性的解释性特征
4. **异常敏感双侧归一化**：解决了传统归一化无法区分"正常范围内"和"正常范围外"的问题，正常范围内输出恒为0
5. **交叉信号放大预测机制**：当多个独立时间序列信号同时偏离基线时，通过指数放大提高异常检测的置信度

### 8.2 技术创新

1. **在线学习的EWMA状态**：检测过程中同步更新基线模型，实现对网络环境变化的自适应
2. **7维IP行为指纹向量**：从协议、对端、流量方向、端口、时间、强度、包大小七个维度全方位刻画主机行为
3. **多层次安全态势感知架构**：预测→检测→分析→关联四层协同，从时间和空间多维度构建完整的安全态势图

### 8.3 对比传统方法的优势

| 传统方法 | 本系统创新方法 | 优势说明 |
|----------|--------------|----------|
| 静态阈值 | EWMA自适应基线 | 随网络变化自动调整，减少误报 |
| 单维度检测 | 多维度融合评分 | 检测隐蔽攻击的能力大幅提升 |
| 独立告警 | 攻击链关联推理 | 还原攻击全貌，辅助安全决策 |
| 事后检测 | 前瞻性预测告警 | 提前15分钟预警，争取响应时间 |
| 描述性IP画像 | 量化行为风险评分 | 从"看数据"到"做判断"的跨越 |
| 简单统计 | 信息论+统计学融合 | 引入Shannon熵、Gini系数等高级度量 |
