# 智慧校园网络安全异常检测系统 — 设计重点难点

> 苏州大学 · 无敌暴龙战队 · 计算机设计大赛 A19 赛题

---

## 一、多维异常检测算法的设计与融合（核心难点）

本项目最大的技术难点在于如何在不依赖机器学习训练集的前提下，实现对未知威胁的有效检测。系统设计了四个互补的算法模块：

**EWMA-EAD** 解决的核心问题是"流量大≠攻击"的误判困境。单纯检测流量突增会在晚间下载高峰时大量误报。为此引入信息熵作为第二维度——正常大流量协议分布均匀（熵高），DDoS 攻击流量高度集中（熵低）。两者通过加权公式融合（0.4×流量偏差 + 0.35×熵偏差 + 0.25×突发性），实现低误报率检测。

**MDTCE** 解决的是告警碎片化问题。APT 攻击由多个低级别事件组成，孤立看每条都不严重。难点在于如何定义两条告警的"关联程度"——系统设计了基于 IP 重叠、时序邻近、地理接近的三维加权边权重，结合 Union-Find 连通分量检测和 Cyber Kill Chain 阶段映射，将碎片告警聚合为可解释的完整攻击链。

**NBF-RS** 的难点是行为指纹的维度选取——既要足够丰富以区分正常与异常，又不能引入大量计算开销。最终选定 7 个可在数据库聚合层直接计算的统计维度（连接多样性、流量不对称度、协议合规度等），无需逐包分析，可在毫秒级完成单 IP 风险评分。

**TPM-PA** 的难点是预测置信度控制。线性回归外推容易产生虚假告警，系统引入"交叉信号放大"机制：只有当流量、熵、连接数三个指标中至少两个同时预测异常时，置信度才乘以 1.4 倍触发预警，大幅降低单指标噪声干扰。

## 二、动态基线替代静态阈值（设计重点）

传统 IDS 依赖固定阈值（如"每分钟超过 1000 个连接即告警"），在校园网络中严重水土不服：白天课时流量与深夜截然不同，节假日与工作日差异巨大，固定阈值要么漏报要么误报。

系统将所有检测阈值改为基于历史数据的**动态基线**（滑动均值 ± 3σ）。难点在于冷启动问题——系统刚部署时历史数据不足，基线不稳定。为此设计了**演示数据预热机制**：系统启动时自动生成 6000 条符合校园网流量规律的初始数据，涵盖正常业务流和多种攻击模式，确保基线在第一次检测时已具备统计意义。

## 三、实时数据流与 WebSocket 推送（设计重点）

仪表盘需要秒级刷新的实时指标，同时后端需要同时服务多个并发 WebSocket 连接，且不能因为某一个客户端的连接异常拖慢整体推送。

设计要点：后端用 `ConcurrentHashMap.newKeySet()` 线程安全地管理所有 Session，每 2 秒由调度线程统一计算指标快照并广播，而非为每个客户端单独计算；前端实现指数退避重连策略（初始 1s → 最大 15s），网络抖动时不会频繁重连打满后端连接数。WebSocket 不可用时自动降级为 HTTP 轮询，保证在复杂网络环境下的可用性。

## 四、PCAP 文件解析与时间基准锚点（技术难点）

系统需要支持导入真实的 PCAP 抓包文件用于分析。难点有两个：

一是 **PCAP 格式兼容**：需处理链路类型 1（以太网）和 101（原始 IP）两种封装格式，正确跳过以太网帧头解析 IP 层，同时处理 TCP/UDP/ICMP 等不同协议的偏移量差异。

二是**时间基准错位**：导入历史 PCAP 后，数据的时间戳是过去某时刻（如两周前），而系统时钟是当前时间，直接查询"最近1小时"会返回 0 条结果。为此设计了 `LatestDataTimeService`，所有时间窗口查询以数据库中最新记录的时间为基准进行偏移计算，无论数据来自何时，都能正确展示相对时间窗口内的内容。

## 五、PostgreSQL CIDR 范围检索（设计重点）

安全分析中常见的需求是"查询来自某个子网的所有流量"（如 `192.168.1.0/24`）。MySQL 原生不支持此类查询，PostgreSQL 提供了 `inet` 数据类型和 `<<= ` 包含运算符，可直接判断某个 IP 是否属于某 CIDR 范围，无需应用层逐条过滤。

难点在于 JPA 无法优雅表达此类查询，系统专门设计了 `FlowSearchJdbcRepository`，绕过 JPA 使用 `NamedParameterJdbcTemplate` 构建动态 SQL，将用户输入的 `*` 通配符转换为 SQL `LIKE`，将 CIDR 表达式转换为 `::inet <<= CAST` 语句，同时支持端口范围区间查询，兼顾检索灵活性与查询性能。

## 六、3D 地球可视化的无资源依赖实现（设计亮点）

ECharts-GL 的 3D 地球通常需要加载外部地图纹理图片，在内网或弱网环境下加载失败会导致地球显示为空白球体。

系统的解决方案是**程序化生成地图纹理**：通过 Canvas API 在前端动态绘制经纬网格和大陆色块作为球体纹理，完全消除对外部图片资源的依赖，同时加入攻击路径大圆弧线和 Jitter 防重叠偏移机制，使地球在任何网络环境下都能正常渲染。
